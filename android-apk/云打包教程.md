# 云打包 APK 傻瓜教程（GitHub Actions，备用方案）

> **本项目主仓库与发布均在 Gitee，不使用 GitHub 作为主发布渠道。**
> 本教程仅作为「本机没有 JDK / Android SDK」时的备用云端打包方案；日常代码提交、APK 发布都以 Gitee 为准。
>
> 目标：不用装 Android Studio、不用装 JDK，只靠一个浏览器，在云端把 `android-apk/` 编译成真正能装的 APK。
>
> 全程约 15 分钟，其中编译 3–5 分钟。
>
> **重要**：GitHub 仓库的根目录必须是 `android-apk` 文件夹里的内容（`settings.gradle`、`app/`、`.github/` 直接暴露在仓库根），不能再多套一层文件夹，否则工作流找不到。

---

## 第 0 步：先确认三件事

- [ ] 有一个 GitHub 账号（没有就去 https://github.com 注册，邮箱验证一下）
- [ ] 电脑上能打开 `ridge-link\android-apk\` 这个文件夹
- [ ] 网页内容已经是最新的（如果不是，先在第 6 步执行一次同步）

---

## 第 1 步：安装 GitHub Desktop（最省事的办法）

1. 打开 https://desktop.github.com/
2. 点 **Download for Windows**
3. 安装后打开，选 **Sign in to GitHub.com**，用刚才的账号登录

> 不想装客户端？直接跳到「附录 B：命令行方式」。

---

## 第 2 步：把 `android-apk` 变成一个仓库

1. GitHub Desktop 菜单：**File → Add local repository…**
2. 点 **Choose…**，选中这个文件夹：

   ```
   C:\Users\21451\Desktop\ct\ridge-link\android-apk
   ```

3. 这时会提示 *"This directory does not appear to be a Git repository. Would you like to create a repository here instead?"*
   → 点 **create a repository**
4. 弹窗里只改两处，其余保持默认：
   - **Name**：保持默认 **`android-apk`** ← ⚠️ 千万不要改
   - **Local path**：应该是 `C:\Users\21451\Desktop\ct\ridge-link` ← 确认这里是 `ridge-link`，不是 `android-apk` 本身
   - **Description**：`山脊信使 RidgeLink Android APK`
   - **Initialize with README**：**不勾**
   - **Git ignore**：`None`
   - **License**：`None`
5. 点 **Create repository**

> 原理：GitHub Desktop 会用「Local path + Name」拼出新仓库的根目录。
> `...\ridge-link` + `android-apk` = `...\ridge-link\android-apk`，正好是我们要的根。
> 如果你把 Name 改成别的（比如 `ridgelink-android`），它会在 `ridge-link` 下**新建一个空文件夹**，里面什么都没有，后面必然失败。
> 远程仓库叫什么名字无所谓，第 3 步发布时再改。

创建完成后，左侧 **Changes** 里应该能看到一堆文件，其中包括：

```
.github/workflows/android-apk.yml
app/build.gradle
build.gradle
gradle.properties
settings.gradle
sync-web.ps1
```

**如果看不到 `.github` 这一项**，说明 workflows 目录不在，先别继续，回到本文档开头检查目录结构。

---

## 第 3 步：发布到 GitHub

1. 点右上角 **Publish repository**
2. 弹窗里：
   - **Name**：`ridgelink-android`
   - **Keep this code private** —— 想公开就取消勾选，想保密就保持勾选（**私有仓库同样可以免费跑 Actions**，每月 2000 分钟额度，够用）
3. 点 **Publish repository**

推送完成后，浏览器打开你的仓库页面，确认能在根目录看到 `app` 和 `settings.gradle`。

---

## 第 4 步：等它自动编译

推送动作会自动触发工作流。

1. 在仓库页面点顶部的 **Actions**
2. 左侧选 **Android APK**
3. 应该能看到一条正在跑的记录（黄色圆点），点进去
4. 展开 **Build Debug APK** 看实时日志

正常流程会经过这些步骤：

```
Checkout
Set up JDK 17
Set up Android SDK
Install SDK packages
Set up Gradle 8.7
Build debug APK        ← 这一步最久，2–4 分钟
List APK output
Upload APK artifact
```

全部变绿（✅）大约 3–5 分钟。

> 如果 Actions 页面提示 *"Workflows aren't being run on this repository"*，说明 `.github/workflows/` 没被推上去。在 GitHub Desktop 里看 Changes 是否有该文件，没有就手动新建确认一次。

---

## 第 5 步：下载 APK

1. 打开那次成功的运行记录
2. 拉到页面最底部，找到 **Artifacts** 区域
3. 点 **RidgeLink-debug-APK** 下载

下载下来是一个 `.zip`，解压后得到：

```
app-debug.apk        ← 这就是安装包
```

> 没登录 GitHub 是下载不了的；用自己的账号登录即可。
> Artifact 默认保留 **30 天**，过期后重新跑一次工作流即可再生成。

---

## 第 6 步：装到手机上

### 方式 A：微信/QQ 传（最简单）

把 `app-debug.apk` 发到手机 → 点开 → 允许「安装未知来源应用」→ 安装。

### 方式 B：数据线 + adb（如果你有）

```bat
adb install -r app-debug.apk
```

### 装好后

- 桌面图标叫「山脊信使」
- 打开直接进入官网首页，全部离线可用（`file:///android_asset/www/index.html`）
- 顶部导航可进「交互演示 / 真实场景 / 计划书 / 路演」
- 按返回键是**页面内后退**，退到首页再按才退出 App
- **飞行模式 / 断网也能正常打开**：所有页面、图标、脚本都在 APK 本地
- 手机端已单独优化：顶部导航可横向滑动、地图可左右滑动、路演页可左右滑动翻页

## 第 7 步：改了网页后怎么重新打包

网页文件在 APK 里是一份**副本**，改了 `ridge-link/*.html` 不会自动进 APK。

每次改完网页，按这个顺序：

1. 打开 PowerShell，进入 `android-apk` 文件夹：

   ```powershell
   cd C:\Users\21451\Desktop\ct\ridge-link\android-apk
   ```

2. 执行同步脚本：

   ```powershell
   powershell -ExecutionPolicy Bypass -File .\sync-web.ps1
   ```

   正常会输出：

   ```
     OK  index.html                ... bytes
     OK  demo.html                 ... bytes
     OK  scene.html                ... bytes
     OK  proposal.html             ... bytes
     OK  pitch.html                ... bytes
     OK  offline-mode.js           ... bytes
     OK  manifest.webmanifest      ... bytes
     OK  sw.js                     ... bytes
     OK  icon-192.png              ... bytes
     OK  icon-512.png              ... bytes
     OK  icon-180.png              ... bytes

   Done: 11 files -> ...\app\src\main\assets\www
   ```

   > 只要有一个页面忘了同步，APK 里就还是旧版。`sync-web.ps1` 会一次同步 5 个页面 + 在线状态条 + PWA 清单 + Service Worker + 3 个图标，共 11 个文件。

3. 回到 GitHub Desktop → 左下角填一句说明（比如 `更新网页`）→ **Commit to main** → **Push origin**
4. 等 Actions 重新跑完，重新下载 APK

## 附录 C：常见失败与处理

| 现象 | 原因 | 处理 |
|---|---|---|
| Actions 页面没有任何运行记录 | `.github/workflows/android-apk.yml` 没推上去 | 检查目录是否为 `仓库根/.github/workflows/android-apk.yml` |
| `Build was configured to prefer settings repositories` | 根 `build.gradle` 又声明了 `allprojects.repositories` | 本工程已修好；若你手动改过，删掉那段 |
| `Plugin [id: 'com.android.application'] was not found` | 没联网拉插件或 settings 里缺 `google()` | 确认 `settings.gradle` 的 `pluginManagement` 含 `google()` |
| `Unsupported class file major version` / `requires Gradle 8.7` | Gradle 版本太低 | 工作流里已固定 `gradle-version: '8.7'`，别删 |
| `failed to find target with hash string 'android-34'` | SDK 没装全 | 工作流已加 `sdkmanager --install platforms;android-34` |
| `Unresolved reference: WebView` 之类 | Kotlin 插件没生效 | 确认 `app/build.gradle` 的 `plugins {}` 里有 `org.jetbrains.kotlin.android` |
| `! [rejected] main -> main (fetch first)` | 远程仓库已有提交 | 先 `git pull --rebase origin main` 再 push |
| 下载 Artifact 提示 404 | 运行还没结束，或已过期 | 等变绿再下；过期就重跑工作流 |
| 手机上装不上（解析包错误） | 下载的是 zip 或文件不完整 | 先解压再传 `app-debug.apk` |

## 附录 D：改应用名 / 版本号 / 图标

### 应用名

改 `app/src/main/AndroidManifest.xml` 里的：

```xml
android:label="山脊信使"
```

### 版本号

改 `app/build.gradle`：

```gradle
versionCode 3          // 每次发新版 +1，不能重复
versionName '1.2'      // 显示给用户看的版本
```

### 图标

把 `ic_launcher.png` 放进 `app/src/main/res/mipmap-*/`，并在清单里加：

```xml
android:icon="@mipmap/ic_launcher"
```

（不弄也能装，只是用系统默认图标。）

## 一句话总结

```
android-apk 推上 GitHub
        ↓  自动
GitHub Actions 编译
        ↓
Actions → Artifacts → RidgeLink-debug-APK
        ↓  解压
app-debug.apk 传到手机安装
```

以后每次改网页：跑一次 `sync-web.ps1` → Commit → Push → 重新下载。
